# Lab log, 2026-11-16: first hardware day of the fabric cell

The first day on the real OARBots: network and isolation, the first arm motion, and the real arms
executing the simulated cell's fabric-twin commands while the operator jogged the simulated gloves.
Read this first tomorrow. The procedures are in `scripts/hw/README.md` and
`docs/fabric-hardware-test-guide.md` §8; this log keeps what happened, why, and what is left.

## Where we stopped

- **Working end to end (22:31-22:40):** gloves jogged in the Isaac plant -> estimator -> `fabric_twin`
  (sensitivity CBF + stretch guard) -> `/oarbot_{blue,silver}/fabric_cbf/cmd_world` -> simulated robots
  and, through `scripts/hw/cmd_relay.py`, each helper's `fabric_cbf_bridge` -> `command_guard` (tablet
  deadman, Fabric Follow) -> both real Kinova arms. Both arms followed the twin "perfectly" (operator);
  the bridges and guards passed 99.9-100 % of the twin's commands (see "The successful run").
- **Code:** branch `jazzy-platform-hardening` at the last commit of this log, pushed to the fork
  (`mtahabekar/oarbots`). Upstream `main` and the lab's `~/ros2_ws` are untouched.
- **Robots at the end of the day:** see the last section; the stock system is restored only after the
  wrap-up steps there.
- **Hardware state:** Blue's wrist camera, Rokubi and gripper are unplugged (`scripts/hw/hosts/blue.args`).
  Blue's Dingo computer does not boot. The NUC was off all day. Both helpers are wired to the switch.

## Decisions and why

| Decision | Why |
| --- | --- |
| Separate `~/fabric_ws` per machine; stock service stopped, never disabled; transient user units; snapshot diff before/after | Others use the robots; a reboot must always restore the stock system, and we must be able to show nothing changed. |
| Session on ROS domain 17, CycloneDDS bound by address | Other people's tools on domain 0 cannot see or command the arms; the laptop adapter carries two IPv4 addresses, so binding by interface name is ambiguous. |
| One branch (`jazzy-platform-hardening`), hardware files in `scripts/hw`, `experiments/hardware`; tags for reference points | User preference: a second branch makes it more complicated. Tags keep sim results reproducible. |
| Fabric work stays on the fork | The stock `*_cd.service` pulls upstream `main` into `~/ros2_ws` and rebuilds at every boot, as root, including `rosdep install`. |
| Deadman is the primary stop; scripts abort only on faults | User: "the deadman switch is enough as a caution". A 5 N raw force check tripped on start-up vibration. |
| Joystick home button for homing, not a script | Exact Home joints and hold-to-run; Kinova's firmware home bypasses the deadman; a Cartesian return cannot settle precisely with the deadband and lag. |
| Real arms execute the twin's `cmd_world` (not a mirror of the simulated hand positions) | User: the robots must move on the decisions of the twin's CBF and stretch guard; that is the purpose. A hand-position mirror written first was deleted. |
| Only `cmd_world` crosses from the simulation (domain 42, Fast DDS) to the robots (domain 17) | Both use the same topic and frame names; sharing a domain would mix TF and joint states. |
| Relay restamps with wall time and scales by the real-time factor (~0.44-0.47) | The twin stamps simulated time (the bridge rejects old stamps); scaling keeps real and simulated arms covering the same distance per second. |
| Bridges use the sim layout (`calibration_exact.yaml`) as their world | Gives each real arm the same motion as its simulated copy relative to its own base; it is not a lab calibration. Real arms start at Home, simulated ones at their grasp, so motions match, not positions. |
| Per-robot boxes measured with MoveIt at 26 points (`BOXES`) | +/-15 cm and +/-12 cm boxes had unreachable points; each robot's outward side approaches the UWB wing and flips the wrist when combined with moving back. |
| Soft box edge (hold outward motion) with a 2 cm hard margin; force stop on the 0.25 s mean | The hard edge and per-sample force stop ended the second run within a minute. |
| Blue's bridge runs without the force stop (`require_force: false`) | Blue has no wrist sensor today. |
| Silver's force stop 15.7 N | The Jaco2's rated payload (1.6 kg). The cell's 6 N placeholder would trip on vibration. |

## Results that matter

- **Gate H3 translation passed on both robots.** Kinova Cartesian x/y/z equals each arm's
  `j2n6s300_link_base` x/y/z; `bridge.yaml`'s `command_frame` is right
  (`experiments/hardware/sessions/2026-11-16_h3_translation/`).
- **Kinova low-speed deadband and lag.** 1 cm/s: no motion; 2 cm/s: almost none; 3-4 cm/s: 65-75 % of
  the command after 0.3-0.6 s. The guard output was a steady 100 Hz and the driver passes it unscaled,
  so this is the arm firmware. The twin's slow corrections are lost; its actuator model needs this.
- **Isolation works.** Every snapshot after setup and sessions matched the baseline.
- **Sim-to-real works**, after the fixes listed below.

## Our own mistakes (so they are not repeated)

- Put the stale-process `pgrep` pattern in the same command line that started the simulation; the sim
  runner's own stale check matched it and refused to start. Start the sim with a clean command line.
- Twice let `~` expand on the laptop instead of the helper (`/home/taha/fabric_ws/...`, then a literal
  `'~'`). Pass helper paths relative to the home folder.
- Read the Kinova sensors without `LD_LIBRARY_PATH`; `InitAPI` returned 2002 and the stock service had
  to be paused twice instead of once.
- The first snapshot script flagged `.pyc` files and the boot-time rebuild as changes; it was rewritten
  to compare source state only.
- Built a hand-position mirror before asking what "move the same as the simulation" meant; it was
  deleted. The intended path (twin commands) already existed.
- Rebuilt on the helpers while the stacks ran; that is a plausible cause of a driver latch. Do not
  rebuild while the arms are live; call `in/start` after any rebuild.
- `bridge.yaml` and the first bridge tests did not consider vibration or box exits during long runs.

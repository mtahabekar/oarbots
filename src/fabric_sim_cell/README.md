# fabric_sim_cell

Runs the fabric perception and state estimator against the simulated OARBot cell in
[`oarbot_simulation`](https://github.com/mtahabekar/oarbot_simulation), treating it as the
physical cell. The plant publishes only device topics (Azure images, registered depth,
camera info, driver joint states, raw Rokubi wrench, `/clock`). Everything in this package is
what a deployment adds: calibration, an optional labelled oracle hand input, a recorder and
scoring against the plant's private truth file.

| Piece | Purpose |
| --- | --- |
| `launch/sim_cell.launch.py` | Joint-state renamers and `robot_state_publisher` per robot, perception per camera, hand fusion or oracle hands, the estimator, optional F/T compensators, optional recorder; all on `use_sim_time` |
| `config/calibration_exact.yaml` | Generated by `oarbot_simulation/tools/export_sim_cell_calibration.py`: map to world, world to bases, end effector to `fabric_grip`, world to `nuc/camera_base`, F/T mass and centre of mass |
| `config/fusion.yaml`, `estimator*.yaml` timing | Fusion and the estimator judge camera liveness on wall-clock time; at the plant's ~0.23x real time the 5 Hz overhead looks silent with the hardware windows, so `max_age_sec` / `max_capture_age_sec` are 1.5 s here |
| `config/estimator.yaml` | Nominal baseline: the plant's sheet (0.84 m, 0.2 kg/m², its Style3D coefficients) on a 15×15 mesh; forces off. `estimator_forces.yaml` turns forces on |
| `config/perception_*.yaml` | Camera perception tuned on plant renders of the dry carbon sheet (value ≤ 130, saturation ≤ 40), 8 cm glove tags and their grip offsets; overhead ROI excludes the robot bases |
| `calibration_publisher` | Publishes the calibration on `/tf_static`; `errors_file` applies deliberate calibration errors |
| `oracle_hands` | **Ideal** hand input from the plant's `/sim/mocap/glove_*`, to isolate the estimator from glove detection; it logs a warning and must be reported as an oracle |
| `grasp_gate` | Passes `/fabric/hand_states` to the estimator only while both Kinova drivers report closed fingers, so estimation starts with the four corners held (launch arg `grasp_gate`, default `true`). Without it the estimator starts during the robots' approach and about half the runs settle into a wrong edge between the robots |
| `recorder` | `/fabric/estimated_state` to the estimator's replay NPZ format, analyses and predictions flagged |
| `evaluate` | Truth interpolated to each state time and the estimator's material coordinates, scored by `fabric_state_estimator.metrics.evaluate` |

Both processes need the same transport profile and domain, so full-resolution frames arrive:

```bash
export FASTRTPS_DEFAULT_PROFILES_FILE=/path/to/oarbot_simulation/config/fastdds_large_messages.xml
export ROS_DOMAIN_ID=42
```

Run the estimator stack with a Python that has NumPy below 2 and Newton (see
`fabric_state_estimator/config/requirements-newton.txt`); build with that interpreter.

`scripts/run_sim_experiment.sh` refuses to start while any sim-cell process (an earlier stack, a
plant) is running, and tears down its own stack's process group at exit: stacks that outlive
their run share every topic and TF frame with the next one. Scores vary between identical runs
(the estimator's analyses depend on message timing), so compare conditions over repeated runs.

## Demo

```bash
# One-time: the robot meshes for RViz
cd ~/ros2_colcon_ws && ~/venvs/fabric_ros/bin/python -m colcon build --packages-select oarbot_description fabric_sim_cell
# Watch one run (~2-3 min): Isaac Sim shows the true cloth, RViz the estimate from sensors only
# (blue sheet, white estimated corners, green = hand positions the estimator receives),
# also drawn over the overhead and wrist images; the requirement scorecard prints at the end
src/oarbots/src/fabric_sim_cell/scripts/run_demo.sh live gloves     # or: live oracle
# The same, but you move the hands (the leader corners) from the keyboard instead of the scripted
# descent: it prints the teleop command to run in a second terminal; 60 s simulated (~4 min)
src/oarbots/src/fabric_sim_cell/scripts/run_demo.sh teleop gloves 60
# live and teleop use the real-time profile (PROFILE=fast, default; plant ~0.45x real time, estimate
# shown ~15 ms behind the plant). PROFILE=full runs the original, slower settings:
PROFILE=full src/oarbots/src/fabric_sim_cell/scripts/run_demo.sh live gloves
# Evidence: the six experiments x 3 (~1 h) and the scorecard (scorecard.md in the output folder)
src/oarbots/src/fabric_sim_cell/scripts/run_demo.sh evidence
ros2 run fabric_sim_cell scorecard <results folder>                  # re-score existing runs
```

The real-time profile is `sim_cell.launch.py profile:=fast` (`estimator_fast.yaml`: 8 x 8 mesh, 16
members, no KLT tracks; `perception_*_fast.yaml`: no tracker, fewer published samples, depth-assisted
glove tags for the plant's half-resolution cameras) with the plant options `run_demo.sh` passes.
Measurements and reasons: oarbot_simulation `SIM_CELL.md`, "Real-time profile".

The scorecard compares each experiment with the online targets proposed in
`docs/fabric-state-estimation-research.md` section 15 (surface p95 <= 50 mm, hand p95 <= 20-30 mm,
capture-to-state age p95 <= 100 ms, calibrated coverage). Latency cannot be judged here: the plant
runs at ~0.23x real time.

## Twin check: the hardware settings in the simulated cell (2026-11-19)

Checks, before robot time, that the twin and its CBF still keep the sheet off the table with the settings changed
on the real cell on 2026-11-19: no limit stops (a virtual collision no longer zeroes the commands), 15 cm/s, the
margins derived from it, and a real obstacle described as a prism with the CBF capsule fitted to it.

```bash
# 0. Prerequisites: the ExtermeLinux disk connected (Isaac Sim 6.2, oarbot_simulation: `mountpoint /media/taha/ExtermeLinux`),
#    no other sim-cell or twin process, and the laptop packages built with the venv:
scripts/hw/fabric_run.sh build-laptop

```

Scenario (both): the live demo's scripted hands, oracle hand input (ideal, so glove detection does not blur the
comparison), the robots grasp at ~9-10 s, the hands hold to ~11 s, descend `DESCENT_M` (default 0.5 m) at 0.1 m/s
toward the table and hold to 25 s (from 1.05 m: 0.5 m leaves the sheet ~10 cm above the 0.32 m table, so the CBF
barely acts; 0.6 m pulls it toward the table); the twin commands both robot grips (`--external-followers`), the plant only clamps them.
Per run (`<mode>_<n>/`): `run_sim_experiment.sh`'s files (truth.npz, plant.log/json, estimate, stack.log, eval),
`twin.npz` and `twin_eval.json`. `report.md`/`report.json` (`twin_check_report.py`): the **true** sheet's clearance
from the **true** table from 10 s (minimum, seconds touching, seconds below the CBF margin), the true robot-grip
speed and rise, the twin's command speeds and time at its cap. The table cannot be detected from the simulated
depth (the plant has no empty background), so `today` takes its prism from the plant's geometry.

One run per mode (the scores vary between identical runs: repeat before deciding). Reading:

- With a 0.5 m descent the sheet never comes near the table (~10 cm); the settings make no difference to safety.
- With 0.6 m the hands pull the sheet toward the table and the CBF must hold the robot grips up. Baseline does
  (8.5 cm). **The speed is the main cause of the loss:** 15 cm/s with the baseline capsule leaves 0.4 cm and lets the
  twin's sheet into its capsule (-2.2 cm). The fitted capsule alone (10 cm/s) costs about 5 cm of the true
  clearance (it is 6 cm lower than the dome) but the CBF still keeps the twin outside it. Together: the true sheet
  touched the table's edge for 0.32 s.
- The CBF margin was derived as twin error + speed x 0.15 s (the twin's delay). It ignores the arms' response lag
  (plant 0.12 s; real arms 0.2-0.8 s, 2026-11-18 joint response): at 15 cm/s, 0.5 s of lag is 7.5 cm. On the real
  arms the shortfall would be larger than here.
- Options (not applied): margin from the measured lag (2 cm + 0.15 m/s x 0.5 s = 9.5 cm) with 15 cm/s; or keep
  10 cm/s for the CBF's planning near an obstacle; or more pad on the fitted capsule. Each can be checked with this
  script (a new twin config + `twin_config:=`) before robot time.
- The follow-up 0.6 m descent at 15 cm/s with the fitted capsule and a 9.5 cm margin cleared the true table
  by 6.25 cm, with zero contact and 2.18 s below 9.5 cm. The twin's minimum clearance from the capsule was
  7.98 cm. Both twin configs now use the 9.5 cm margin.

## Intermittent validation and lean plant

`PROFILE=monitor scripts/run_demo.sh live gloves` starts fabric checks at 5 Hz, with an
adaptive reduction to 1 Hz after sustained acceptable pre-correction depth residuals.
Overhead images and gloves remain at 5 Hz. With oracle hands, overhead capture can also
fall to 1 Hz. Bad checks or expired feedback restore the higher rate. Continuous state
prediction and future forecasts are disabled; timestamps identify checked captures.
This is camera/model agreement, not physical material identification.

`PROFILE=lean` adds an approximate 28x28-cell plant (29x29 particles), eight substeps with
six outer/three inner iterations, and a 7-cell CBF predictor. Sheet dimensions, areal density
and 3 cm grip span are preserved. It trades some plant fidelity for speed; the combined
simulation's `PERFORMANCE_REVIEW.md` records fine-versus-coarse geometry, tension, runtime
and strict controller-feasibility checks. `fast` keeps the fine plant and remains default.

The fast/monitor/lean paths now use synchronized manually scheduled camera capture.
Rebuild `fabric_perception`, `fabric_state_estimator`, and `fabric_sim_cell` before use.

## Extended material-identification warm-up

Use `twin_config:=/absolute/path/to/config/twin_identification.yaml` with
`twin:=true twin_commands:=true twin_bank:=true twin_adapt_period_sec:=10.0`.
The plant must use `--attach --route-cbf --external-followers`. Keep the two
human-side corners stationary and the fabric clear of obstacles. This opt-in
configuration starts at simulation time 15 s; the ordinary twin configuration
retains the original warm-up.

The sequence adds 3 cm transverse compression, alternating 5 cm robot-grip
lifts, and lateral shifts of +/-3 cm after the original inward slack stages.
It returns to the slack pose between lift stages and to the original pose at
completion. Transitions use the configured speed and holds use `hold_sec`.
The CBF and stretch guard still filter these nominal motions: identification
uses measured grip trajectories, not an assumption that every target was reached.
No force-loading experiment, free-corner mode, or contact identification is added.

New YAML settings in `warmup` are `transverse_m`, `lift_m`, and `lateral_m`
(each defaults to zero, range 0 to 0.1 m). The dimensions are experimental
starting values, not validated hardware excursions. The parameter bank retains
up to approximately five minutes at nominal topic rates and logs
`calibration started` before its blocking candidate search. Allow the search to
complete; increasing motion duration alone does not accelerate fitting.

Compare baseline and extended runs with identical plant coefficients, initial
conditions, solver settings and sensor settings. Record parameter releases and
calibration cost, compare recovery of bend=2 and shear=0.5, and validate on an
unseen motion. Repeat runs because sensor timing varies. A run without a completed
calibration is inconclusive, and low corrected shape error is not parameter recovery.

Validation: CPU trajectory tests confirm bounded commands, return to origin,
mirrored lifts and additional lateral/vertical excursion compared with baseline.
Improved material recovery has not yet been established by a paired plant experiment.

### GPU comparison (15 November 2026)

Ran on NVIDIA RTX 5070 Laptop GPU, Newton 1.6.1 / Warp 1.17.0.
The existing calibration-recovery and baseline warm-up tests both passed;
the four CPU extended-trajectory tests also passed.

A paired synthetic experiment with a 16-cell mesh, known scales (2, 0.5),
exact surface observations, no feedback, no CBF and a 25-candidate search gave:

| Sequence | Holds | Recovered bend / shear | Total generation + fitting time |
| --- | --- | --- | --- |
| Baseline | 4 | 2.0 / 0.5 | 72.9 s |
| Extended | 13 | 2.0 / 0.5 | 236.4 s |

Both recovered the coefficients exactly on the search grid. The extended
sequence did **not** improve parameter accuracy in this experiment and cost
about 3.2 times as much. Its lower fitting residual is not a fair accuracy
comparison because the two datasets contain different poses. Keep the extended
sequence experimental; improvement under rendered sensor noise remains untested.

Reproduce from the oarbots root on a GPU-enabled host:

```bash
PYTHONPATH=src/fabric_twin \
FABRIC_SIM_ROOT=$HOME/ros2_colcon_ws/src/fabric_sim_isaacsim_newton \
~/venvs/fabric_ros/bin/python src/fabric_twin/scripts/compare_warmups.py /tmp/warmup_comparison.json
```

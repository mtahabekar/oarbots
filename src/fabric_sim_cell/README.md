# fabric_sim_cell

Runs the fabric perception and state estimator against the simulated OARBot cell in
[`oarbot_simulation`](https://github.com/mtahabekar/oarbot_simulation), treating it as the
physical cell. The plant publishes only device topics (Azure images, registered depth,
camera info, driver joint states, raw Rokubi wrench, `/clock`). Everything in this package is
what a deployment adds: calibration, an optional labelled oracle hand input, a recorder and
scoring against the plant's private truth file.

| Piece | Purpose |
| --- | --- |
| `launch/sim_cell.launch.py` | Joint-state renamers and `robot_state_publisher` per robot, perception per camera, hand fusion or oracle hands, the estimator, optional F/T compensators, optional recorder; all on `use_sim_time` |
| `config/calibration_exact.yaml` | Generated by `oarbot_simulation/tools/export_sim_cell_calibration.py`: map to world, world to bases, end effector to `fabric_grip`, world to `nuc/camera_base`, F/T mass and centre of mass |
| `config/fusion.yaml`, `estimator*.yaml` timing | Fusion and the estimator judge camera liveness on wall-clock time; at the plant's ~0.23x real time the 5 Hz overhead looks silent with the hardware windows, so `max_age_sec` / `max_capture_age_sec` are 1.5 s here |
| `config/estimator.yaml` | Nominal baseline: the plant's sheet (0.84 m, 0.2 kg/m², its Style3D coefficients) on a 15×15 mesh; forces off. `estimator_forces.yaml` turns forces on |
| `config/perception_*.yaml` | Camera perception tuned on plant renders of the dry carbon sheet (value ≤ 130, saturation ≤ 40), 8 cm glove tags and their grip offsets; overhead ROI excludes the robot bases |
| `calibration_publisher` | Publishes the calibration on `/tf_static`; `errors_file` applies deliberate calibration errors |
| `oracle_hands` | **Ideal** hand input from the plant's `/sim/mocap/glove_*`, to isolate the estimator from glove detection; it logs a warning and must be reported as an oracle |
| `grasp_gate` | Passes `/fabric/hand_states` to the estimator only while both Kinova drivers report closed fingers, so estimation starts with the four corners held (launch arg `grasp_gate`, default `true`). Without it the estimator starts during the robots' approach and about half the runs settle into a wrong edge between the robots |
| `recorder` | `/fabric/estimated_state` to the estimator's replay NPZ format, analyses and predictions flagged |
| `evaluate` | Truth interpolated to each state time and the estimator's material coordinates, scored by `fabric_state_estimator.metrics.evaluate` |

Both processes need the same transport profile and domain, so full-resolution frames arrive:

```bash
export FASTRTPS_DEFAULT_PROFILES_FILE=/path/to/oarbot_simulation/config/fastdds_large_messages.xml
export ROS_DOMAIN_ID=42
```

Run the estimator stack with a Python that has NumPy below 2 and Newton (see
`fabric_state_estimator/config/requirements-newton.txt`); build with that interpreter.

`scripts/run_sim_experiment.sh` refuses to start while any sim-cell process (an earlier stack, a
plant) is running, and tears down its own stack's process group at exit: stacks that outlive
their run share every topic and TF frame with the next one. Scores vary between identical runs
(the estimator's analyses depend on message timing), so compare conditions over repeated runs.

## Demo

```bash
# One-time: the robot meshes for RViz
cd ~/ros2_colcon_ws && ~/venvs/fabric_ros/bin/python -m colcon build --packages-select oarbot_description fabric_sim_cell
# Watch one run (~2-3 min): Isaac Sim shows the true cloth, RViz the estimate from sensors only
# (blue sheet, white estimated corners, green = hand positions the estimator receives),
# also drawn over the overhead and wrist images; the requirement scorecard prints at the end
src/oarbots/src/fabric_sim_cell/scripts/run_demo.sh live gloves     # or: live oracle
# The same, but you move the hands (the leader corners) from the keyboard instead of the scripted
# descent: it prints the teleop command to run in a second terminal; 60 s simulated (~4 min)
src/oarbots/src/fabric_sim_cell/scripts/run_demo.sh teleop gloves 60
# live and teleop use the real-time profile (PROFILE=fast, default; plant ~0.45x real time, estimate
# shown ~15 ms behind the plant). PROFILE=full runs the original, slower settings:
PROFILE=full src/oarbots/src/fabric_sim_cell/scripts/run_demo.sh live gloves
# Evidence: the six experiments x 3 (~1 h) and the scorecard (scorecard.md in the output folder)
src/oarbots/src/fabric_sim_cell/scripts/run_demo.sh evidence
ros2 run fabric_sim_cell scorecard <results folder>                  # re-score existing runs
```

The real-time profile is `sim_cell.launch.py profile:=fast` (`estimator_fast.yaml`: 8 x 8 mesh, 16
members, no KLT tracks; `perception_*_fast.yaml`: no tracker, fewer published samples, depth-assisted
glove tags for the plant's half-resolution cameras) with the plant options `run_demo.sh` passes.
Measurements and reasons: oarbot_simulation `SIM_CELL.md`, "Real-time profile".

The scorecard compares each experiment with the online targets proposed in
`docs/fabric-state-estimation-research.md` section 15 (surface p95 <= 50 mm, hand p95 <= 20-30 mm,
capture-to-state age p95 <= 100 ms, calibrated coverage). Latency cannot be judged here: the plant
runs at ~0.23x real time.

## Intermittent validation and lean plant

`PROFILE=monitor scripts/run_demo.sh live gloves` starts fabric checks at 5 Hz, with an
adaptive reduction to 1 Hz after sustained acceptable pre-correction depth residuals.
Overhead images and gloves remain at 5 Hz. With oracle hands, overhead capture can also
fall to 1 Hz. Bad checks or expired feedback restore the higher rate. Continuous state
prediction and future forecasts are disabled; timestamps identify checked captures.
This is camera/model agreement, not physical material identification.

`PROFILE=lean` adds an approximate 28x28-cell plant (29x29 particles), eight substeps with
six outer/three inner iterations, and a 7-cell CBF predictor. Sheet dimensions, areal density
and 3 cm grip span are preserved. It trades some plant fidelity for speed; the combined
simulation's `PERFORMANCE_REVIEW.md` records fine-versus-coarse geometry, tension, runtime
and strict controller-feasibility checks. `fast` keeps the fine plant and remains default.

The fast/monitor/lean paths now use synchronized manually scheduled camera capture.
Rebuild `fabric_perception`, `fabric_state_estimator`, and `fabric_sim_cell` before use.
